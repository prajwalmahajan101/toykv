# toykv v1.0.0

Single-node in-memory KV store in Go — RESP2 protocol subset, AOF persistence, TTL, companion CLI and TUI. v1.0.0 closes the 10-milestone roadmap and ships the project as a tagged release.

## What's in the archive

Each `toykv_1.0.0_<os>_<arch>.tar.gz` carries:

- `toykv` — server binary
- `toykv-cli` — RESP2 CLI (one-shot / REPL / piped / raw modes)
- `toykv-tui` — Bubble Tea TUI (two-pane keys/value, raw RESP prompt, all PRD §5.5 keybindings)
- `README.md`, `LICENSE`, `CHANGELOG.md`
- `docs/PRD.md`, `docs/ROADMAP.md`, `docs/SECURITY.md`

Verify: `sha256sum -c SHA256SUMS`.

Platforms shipped: `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`. Static, CGO-disabled. No Windows in v1; see [ADR-0010](../adr/0010-release-artefacts-and-distribution.md) for the cut rationale.

## Highlights

- **15 commands, byte-compatible with `redis-cli`** across the supported subset (`PING`, `ECHO`, `GET`, `SET [EX|PX|NX|XX]`, `DEL`, `EXISTS`, `EXPIRE`, `PEXPIRE`, `PEXPIREAT`, `TTL`, `PTTL`, `PERSIST`, `INCR`, `DECR`, `KEYS`, `FLUSHDB`, `DBSIZE`, `BGREWRITEAOF`). Exercised on every CI run by both `go-redis/v9` and a real `redis-cli` sweep against the shipped binary.
- **Strong durability under `appendfsync=always`** — zero acknowledged-write loss across SIGKILL + restart, proven by `internal/server/aof_crash_test.go` and the M9 composition soak in `test/chaos/`.
- **`BGREWRITEAOF` compaction** with crash-safe atomic rename (ADR-0005). Survives kill at any point during the rewrite; exactly one of `{old .aof, new .aof}` is canonical on restart.
- **TTL with lazy + 1 Hz sweep eviction**, persisted via AOF v2 records (ADR-0004 absolute-PXAT encoding); replay accepts both v1 and v2 records.
- **Companion `toykv-cli`** — stdlib-only, modelled on `redis-cli`. Auto-detects one-shot / REPL / piped modes from `os.Args` and `os.Stdin.Stat()` (ADR-0008).
- **Companion `toykv-tui`** — Bubble Tea, two-pane layout, 2 Hz refresh via `tea.Cmd` (no goroutine-into-Program races), injectable `Doer` for unit testability (ADR-0009).

## Limits — please read

- **No auth, no TLS, no IP allowlist.** v1 binds to `127.0.0.1` by convention and `:6390` by default. Do not expose to networks you don't fully trust. Full threat model: [`docs/SECURITY.md`](../SECURITY.md).
- **Single-node only.** No replication, no clustering, no `tinyraft` integration. v3 is where that lives, if it ever does — see [ROADMAP §v3.0](../ROADMAP.md#v30--distributed-the-tinyraft-payoff).
- **Strings only.** Lists / hashes / sets / sorted sets / pub-sub are v2/v3 backlog. PRD §5.1 is the entire wire surface.

## Numbers (recorded, not promised)

`valkey-benchmark -n 100000`, 13th-gen i7-1355U + NVMe, warm page cache:

| fsync | `SET` p50 | `SET` rps | `GET` p50 | `GET` rps |
|---|---|---|---|---|
| `always`   | 0.295 ms |  80 515 | 0.359 ms |  67 843 |
| `everysec` | 0.479 ms |  55 340 | 0.471 ms |  56 148 |
| `no`       | 0.487 ms |  53 908 | 0.319 ms |  72 780 |

`always` came out fastest on warm NVMe — `fdatasync` is cheaper than the per-request RESP+mutex overhead at this scale. On slower disks the conventional `no > everysec > always` ordering returns. Full methodology + how to reproduce: [`docs/BENCHMARKS.md`](../BENCHMARKS.md). These are *not* a regression gate.

## Install

```sh
VERSION=v1.0.0
OS=$(uname -s | tr '[:upper:]' '[:lower:]')
ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -L "https://github.com/prajwalmahajan101/toykv/releases/download/${VERSION}/toykv_${VERSION#v}_${OS}_${ARCH}.tar.gz" \
  | tar -xz -C /usr/local/bin
toykv --help
```

Or from source: `git clone https://github.com/prajwalmahajan101/toykv && make build`.

## Looking ahead

Default trajectory after v1.0.0 is **Option A — ship and stop** (see [ROADMAP §"Honest framing"](../ROADMAP.md#honest-framing--pick-one-trajectory)). v2 (single-node useful — AUTH, lists, hashes, `INFO`, `SCAN`) and v3 (distributed via `tinyraft`) stay backlog-only until real usage justifies them. The spec was emphatic: *"that's how you end up half-building Redis instead of finishing tinykv."*
