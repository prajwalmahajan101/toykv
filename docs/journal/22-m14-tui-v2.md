# 22 — M14: TUI v2

**Date:** 2026-07-17
**Branch:** `feat/tui-v2` → **PR pending**. Seven commits, dependency-ordered: `-a` AUTH flag → SCAN paging + INFO status bar + AUTH prompt (the coupled core) → hash field:value rendering → help/usage + retire client-side glob → unit tests (17) → `teatest` smokes (owned risk test) → LLD §7.6 delta. ADR-0015 + this entry ride the branch (same in-branch call as M12/M13).
**Trigger:** The v1 TUI predated the whole v2 surface — string-only values, `KEYS *`-loads-everything iteration, a `-fsync` *label* the user typed in by hand, and no notion of a password-protected server. M14 is the consumer milestone that finally spends M11 (types), M12 (auth), and M13 (SCAN/INFO) in one client.

## Decision / surprise

1. **M14 was projected "no new ADR," but two calls draw real boundaries — so ADR-0015 exists.** Most of M14 genuinely is consumption (types render via `respfmt`, AUTH via the M12 gate, INFO via the M13 verbatim form). The two that aren't: (a) the keys-pane paging keeps a *client-side cursor stack* for back-navigation, and the deliberate decision is that the stack is **UX only** — it carries no consistency contract; a popped cursor re-scans live data, and the sole guarantee is ADR-0014's server-side SCAN promise. (b) TLS-client dialing is **deferred** — the shared `internal/client` stays plain-TCP + AUTH even though M12 gave the server TLS. Both are "what the client deliberately does *not* guarantee" boundaries — the same test ADR-0014 cleared against the same "none new" projection.

2. **Filtering had to move server-side, which quietly retired a whole file.** v1's `/` filtered a locally-materialised key slice with a bespoke `globMatch` (`glob.go`). Once paging means "one SCAN page at a time," the filter *must* become `SCAN MATCH` — otherwise you're still pulling the whole keyspace to filter it client-side, defeating the point of adopting SCAN. So `/` now sets the MATCH pattern, `visibleKeys()` returns the page as-is, and `globMatch` is deleted. The one piece kept: `globLiterals`, which highlights the matched span in each name — that's presentation, not filtering.

3. **The AUTH prompt fights the refresh tick, and the fix is to pause the tick.** The TUI polls every 2s. If the server needs a password, every poll trips `-NOAUTH` — and naively that re-enters the password prompt, wiping whatever the user has typed so far. The fix: `enterAuthPrompt()` is idempotent (a second `-NOAUTH` while already in `ModeAuth` is a no-op), *and* the tick handler skips the refetch entirely while `ModeAuth` is up (it just re-arms the tick to keep the chain alive). Password typing is now uninterruptible.

4. **A `-race` test flake taught the shape of teatest's output.** The paging smoke first asserted "after `]`, page-1 key `k000` is *gone* from the view." It passed alone and failed in the full `-race` suite. Cause: `teatest`'s `Output()` is the **cumulative** frame stream, not the current screen — once `k000` was ever drawn it's in the buffer forever, so `!contains("k000")` can never hold. Replaced with a *positive* assertion on `k050` (which lives only in page 2's SCAN range, seq 51–100), which is the real proof paging advanced. Lesson: assert on what *appears* in a cumulative stream, never on what should have disappeared.

## Why it mattered

- **A consumer milestone still has boundaries worth recording.** The easy read of M14 is "wire up M11–M13 in the TUI, no decisions." But the interesting calls in a consumer are the *non-guarantees*: the client deliberately doesn't promise stable pages, and deliberately can't reach a TLS server yet. Writing those down (ADR-0015) is what stops a future reader assuming the cursor stack is a snapshot or that TLS was forgotten.
- **The migration forces the filter decision.** "Add paging" sounds like a view change; it's actually a filter-semantics change (client glob → server `path.Match`). Following the adoption of SCAN to its conclusion — you can't page *and* filter client-side — is what turned a feature into a small behavior-boundary shift, cleanly retiring a file instead of leaving dead code.
- **Know your test harness's model.** The flake wasn't timing (bumping the timeout didn't fix it); it was asserting against the wrong mental model of teatest. Positive assertions on a cumulative stream are robust; negative ones are a trap.

## Code / measurement

- **Paging.** `Model` gains `pageCursor`/`nextCursor`/`cursorStack []uint64`/`pageCount` (COUNT hint, default 50). `fetchRefresh(c, pattern, cursor, count, focused, gen)` issues `SCAN cursor MATCH pattern COUNT n`, then per-key `TYPE`+`TTL`, then the focused value by kind, then `INFO`. `]`/`[` (+ PgDn/PgUp) page; `resetPaging()` on filter change / FLUSHDB.
- **Typed fetch/render.** `doValue` branches on kind: `GET` (string) / `LRANGE 0 -1` (list) / `HGETALL` (hash); size derived from the reply (bytes / elements / fields) — no extra `LLEN`/`HLEN` round-trip. Value pane renders string (quoted), list (numbered, shared `respfmt`), hash (`field: value` pairs read two-at-a-time from the RESP2 flat array).
- **INFO status.** `parseInfo` pulls `appendfsync`/`uptime_in_seconds`/`connected_clients`/`db0:keys=` from the verbatim body; `-fsync` becomes `StatusLine.FsyncOverride` (wins when set). Header adds `up=`/`clients=`.
- **AUTH.** `ModeAuth` masked prompt (`textinput.EchoPassword`) on any `-NOAUTH` (refresh or reply path); `authCmd` sends `AUTH`; `-a` flag authenticates at launch. TLS deferred.
- **Removed:** `internal/tui/glob.go` + `glob_test.go` (client-side `globMatch`).
- **Tests:** `m14_test.go` (17: parseInfo incl. empty-keyspace + `db0:keys=N,expires` split, doScanPage argv/cursor, doType/doValue by kind, `]`/`[` cursor-stack push/pop + last/first-page no-ops, filter-submit reset, `-NOAUTH`→masked prompt on both paths, AUTH submit unmasks + sends, tick-during-auth no refetch, formatUptime, INFO header, `-fsync` override, page indicator, hash view). `smoke_test.go` (+3 teatest: typed views, multi-page paging, auth prompt; `startServerWith(requirePass)`). `go test -race ./...` green across all packages incl. chaos + e2e; `make lint` 0 issues.

## Follow-ups

- **TLS-client dialing** (v2.x backlog, ADR-0015). The TUI/CLI can't reach a TLS-only server until `internal/client` grows a TLS dial path.
- **`TYPE`+`TTL` per key per page** = ~100 sequential calls for a full 50-key page on a non-pipelining client (ADR-0009). Fine at toy scale; if it bites, pipeline the client — not a paging redesign.
- **Page-back is not a snapshot.** Documented (LLD §7.6, page indicator), but a user expecting stable pages may be surprised; a "pin snapshot" mode is a possible future affordance (explicitly rejected as a default in ADR-0015).
- **ROADMAP M14 → ✅ flipped; PR still to open.** Flip the PR-column link from `feat/tui-v2 (PR pending)` to the real PR number on open, mirroring M13/#31.
