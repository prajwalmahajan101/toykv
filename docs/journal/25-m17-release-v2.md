# 25 — M17: Bench + polish + v2.0.0 release

**Date:** 2026-07-18
**Branch:** `feat/release-v2` (10 commits, rebase-merged to `main` via PR #36, CI green across Ubuntu + macOS × Go 1.25/1.26 + lint/build/chaos-smoke). Order: exit-criteria evidence → `fix(resp)` DoS bounds → security-review doc → `perf(telemetry)` memoization → ADR-0017 amendment → typed bench → roadmap reconcile → version bump + CHANGELOG cut → README/SECURITY/PRD/HLD/LLD deltas → roadmap PR marker.
**Trigger:** last milestone of the committed v2 arc — cut `v2.0.0`. Framed as bench + polish + tag. **Stopped before the tag** by design: prepared the release PR, left the `git tag v2.0.0` + goreleaser trigger to the maintainer.

## Decision / surprise

1. **The milestone was a verification milestone, and verification found real bugs.** The recall lesson ("a roadmap records *intended*, not *verified*, state — confirm each checkpoint against live code before authoring the plan") was the whole game. A parallel Explore against the gate list showed ~all of it already satisfied by M10–M16 (flaky test properly `-short`-skipped, `.golangci.yml` already `version: "2"`, AOF-upgrade tests present, OTel no-op path present, goreleaser/CHANGELOG present, `serverVersion = "2.0.0-dev"`). So M17 collapsed to: produce fresh evidence, do the one new deliverable (security review), re-bench, reconcile docs, bump version. Then the "verification" turned up **two genuine regressions the roadmap's happy-path never anticipated** (below). The lesson earned its keep: had I trusted the roadmap's "gates green," both would have shipped in `2.0.0`.

2. **The security review of auth/TLS came back clean — and found two pre-auth DoS vectors one layer down.** Scoped a dedicated adversarial agent at the M12/M15 surface (constant-time compare, pre-auth gate, TLS, protected-mode loopback policy) — all verified solid. But it surfaced the RESP codec *underneath* the auth gate: `readArray` did `make([]Value, n)` with `n` bounded only against negative (a `*1000000000\r\n` header → multi-GB alloc → OOM), and recursed via `ReadFrame` with no depth cap (nested `*1\r\n` → stack-exhaustion *fatal* panic, un-`recover`-able). Both reachable by one tiny packet **before** the auth gate — defeating the exact "safe-by-default" thesis that earns `2.0.0`. Verified against source before acting, then fixed: `MaxArrayLen = 1<<20` (matches Redis `proto-max-multibulk-len`), `MaxDepth = 32`, both reject with `ErrTooLarge` before allocation, threaded a depth counter through `readFrame`. Commit `ef8a423`, three regression tests. *A clean bill on the named surface is not a clean bill on the reachable surface.*

3. **"OTel-off is a true no-op" was false by ~20% — and the parity benchmark existed but had never been *run against the pre-M16 binary*.** The gate says off-by-default must be benchmark-parity with pre-M16. `BenchmarkObserveCommand_Disabled` measured the disabled path in isolation (29 allocs/op) but nobody had done the actual A/B. Did it (built the pre-M16 binary `a3d62e1` in a worktree, interleaved n=4 rounds vs the v2 binary): **SET −21%, GET −18%**, consistent across every round. Root cause: building an `attribute.Set` or a `metric` option **allocates even against no-op providers**, so `observeCommand` rebuilding them per command (4× `WithAttributes` + a 3-attr span `SetAttributes`) taxed the disabled path. ADR-0017's "no-op providers make it free, no guard needed" assumption was simply wrong. Surfaced it as a decision rather than silently choosing; the maintainer picked *deeper optimization, keep the no-guard design*. Memoized per-command instrument attributes in a `cmdInstr` cache (bounded label set) — `attribute.Set`-backed options + spread-at-`Start` span options — **no `if enabled` guard added**. Disabled path 29 → 14 allocs/op, 3923 → 1757 ns/op; SET back to parity, GET within ~7% (the residual floor is the two irreducible no-op `Tracer.Start` context allocations). Commit `980dceb`, ADR-0017 amended (`574668c`), `TestObserveCommand_Disabled_AllocBudget` (≤16) pins it.

4. **Protected mode fought the benchmark — which is the feature working.** First bench run produced empty output; the server was refusing to start on `:6390` because the unspecified host is non-loopback and no auth/TLS was set (M15). Had to bind explicit `127.0.0.1:6390`. A satisfying live confirmation that the earned-major break does exactly what it says.

5. **`redis-benchmark` wasn't installed — but the v1 baseline had already solved that.** The v1.0.0 BENCHMARKS entry used `valkey-benchmark` from `valkey/valkey:8-alpine` via `docker run --network host`. Reused that exact tooling on the same laptop, so the v2 numbers are methodology-comparable to v1. (The numbers themselves are noisier — a 5-command sustained run on a fanless mobile i7 throttles — but that's honesty, not regression.)

6. **The session died mid-flight and the doc-drafting fork died with it.** Delegated README/SECURITY/PRD/HLD/LLD deltas to a context-inheriting fork; the process exited before it finished (only a partial README command-table edit survived — kept, it was correct). Finished the five docs inline. Reminder that a background fork's in-process state is not durable across a harness restart — checkpoint or keep long doc edits inline.

## Why it mattered

- **The gate is only as good as the evidence you run *this session*.** Two "already green" items were regressions. The release-hardening gate exists precisely to catch the thing the roadmap's optimism papers over — and it only works if you re-run it, not re-read it.
- **Semver honesty is the whole story of this release.** `2.0.0` is earned by M15's protected mode, and both findings threatened that: a pre-auth DoS makes "safe-by-default" a lie, and a 20% telemetry tax makes "additive / off is free" a lie. Fixing both is what keeps the major honest, not just the version string.
- **Surface the design fork, don't silently narrow it.** Same pattern as M16's ctx-in-store call: when the fix reverses a documented ADR decision (the no-guard design), that's a maintainer decision, not a release-prep edit. Asked; got "optimize, keep no-guard"; delivered exactly that.

## Code / measurement

- **DoS bounds** (`ef8a423`): `internal/resp/errors.go` (`MaxArrayLen = 1<<20`, `MaxDepth = 32`), `reader.go` (`readFrame(depth)` threading + pre-alloc rejects). Tests: `TestReader_ReadFrame_OversizedArray`, `_OverDeepNesting`, `_NestingWithinDepthOK`.
- **Telemetry memoization** (`980dceb`): `internal/server/instrument.go` `cmdInstr` cache built in `New`; `observeCommand` reads precomputed `MeasurementOption`s + `[]SpanStartOption`. Disabled path **29 → 14 allocs/op, 3923 → 1757 ns/op**. `TestObserveCommand_Disabled_AllocBudget` (≤16).
- **OTel-off A/B** (pre-M16 `a3d62e1` vs v2, `everysec`, valkey-benchmark, n=4): before fix SET −21% / GET −18%; after fix SET at parity, pipelined GET within ~7%.
- **Typed bench** (`9a7ffcc`, optimized binary, 3 fsync policies × set/get/lpush/rpush/hset): recorded in `docs/BENCHMARKS.md`; GET steady ~57–61k rps, mutations in the same band as SET (shared store-mutex + AOF path).
- **Release mechanics**: `serverVersion` `2.0.0-dev` → `2.0.0` (`97e4f6d`); CHANGELOG cut `[Unreleased]` → `[2.0.0] — 2026-07-18`, adding the M13/M14/M16 entries that were missing + the earned-major note. `make ci` fully green (fmt-check + vet + lint 0 issues + `-race ./...`).
- **Security review**: `docs/SECURITY-REVIEW-v2.md` — clean bill on the auth/TLS/protected-mode surface, two BLOCKING codec findings fixed, zero unwaived blockers.
- **Docs**: README v2 posture + stale "no auth" warning fixed; SECURITY (SCAN/TUI-AUTH stale limits fixed, DoS-bounds + review link); PRD §5.8 / HLD §16 / LLD §5.7–5.8 v2 deltas; ROADMAP (8 ADR topics / 7 files, gate outcomes, M17 status). ADR index budget note was already current (14 written, incl. 0017).

## Blog-worthy?

Strong material. Two clean stories: **(1)** "the release gate found the bug the roadmap said didn't exist" — a security review scoped at auth that found a pre-auth DoS one layer down, plus a 20%-regression that the *existing* parity benchmark would have caught if anyone had run the A/B. **(2)** "no-op providers are not free" — the OpenTelemetry lesson that building attribute sets / metric options allocates regardless of whether the SDK records, so a guardless disabled path still costs ~20% until you memoize the immutable parts. Quote the before/after allocs (29 → 14) and the ADR-0017 amendment ("the parity benchmark, not the assumption, is the contract"). Meta-lesson worth a paragraph: a milestone framed as "polish" was where the two most interesting bugs of the whole v2 arc surfaced — because it was the first time anything was *verified* rather than *built*.
