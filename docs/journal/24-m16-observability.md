# 24 — M16: Observability (OpenTelemetry → LGTM)

**Date:** 2026-07-18
**Branch:** `feat/observability` (14 commits, dependency-ordered: telemetry pkg skeleton → OTLP exporters/providers → `-otel-*` flags + Config wiring → command RED metrics → connection/auth/TLS metrics → keyspace/sweeper/AOF/replay/process metrics → `connState` context refactor → connection/command spans → `store.<op>` spans + hashed keys → AOF/sweeper spans → slog→OTLP bridge → local LGTM compose → 4 owned-risk tests → ADR-0017 + docs + this entry).
**Trigger:** the v2 goal-word is "deployable, safe-by-default, **observable** single node." M10–M15 built every surface; M16 makes *observable* true — the three signals over OTLP to a Grafana LGTM stack — without moving the semver needle (M15's protected mode still earns `2.0.0`).

## Decision / surprise

1. **Off-by-default is achieved by *construction*, not a guard.** `telemetry.Init` installs the SDK's own no-op `TracerProvider`/`MeterProvider`/`LoggerProvider` as the OTel globals when `-otel-endpoint` is empty. Every instrument handle and span-opener is built against those globals and called *unconditionally* — a no-op span/measurement is the disabled cost. There is **no `if enabled`** scattered through the server. The parity benchmark (`BenchmarkObserveCommand_Disabled`) is the backstop against a future change making the disabled path do real work.

2. **The `store.<op>` span churn call — asked, then avoided.** The inventory shows `store.<op>` as a child of `command`, which the literal reading threads `context.Context` into ~30 store methods. Measuring first showed the real cost: **~250 call-site edits, almost all in store unit tests, for byte-identical emitted telemetry.** Surfaced it as a decision (the plan explicitly said to, rather than silently narrow) → chose to create the span at the **server→store boundary** in `observeCommand`, parented to the command span, reading `hit`/error from the reply. The store package stayed completely ctx-free. Same trace tree, ~0 test churn. Lesson locked: *the means (ctx in store) was never the goal (the span) — measure the churn before committing to the literal design.*

3. **The AOF span is a pure outer wrapper — that's what keeps durability safe.** `aof.append` wraps the whole `appendIfLive` → `Writer.Append` call (which does append **then** fsync internally). A slow fsync still shows as span latency, so the durability-latency trace signal survives, but the span *cannot* reorder anything inside the writer. The M3/M11 crash suite (`test/chaos`) + e2e stayed green with tracing compiled in — the explicit owned-risk assertion. Consequence: the separate `aof.fsync`/`snapshot`/`finalize` sub-spans in the inventory are **not** emitted (fsync latency is the `aof.fsync.duration` metric); `aof.rewrite`/`aof.replay` are roots (rewrite is async and replies before it runs). Recorded as as-built deviations in the inventory + ADR-0017.

4. **`go mod tidy` prunes deps until first import — so deps land with their usage.** Fetched the whole OTel module set up front; the first `tidy` dropped everything not yet imported (exporters, contrib, otelslog). Rather than fight it, let each task's first import re-add its module. Cleaner history: the go.mod delta in each commit is exactly what that commit uses.

5. **Exporter-down resilience is almost free.** OTLP exporters connect lazily and batch asynchronously, so a dead collector never blocks a command; a global `otel.ErrorHandler` logs `otel export failed (dropped)` and drops the batch. The one thing that *is* fatal — a malformed `-otel-protocol` — is surfaced before the listener opens (exit 2), distinct from an unreachable endpoint (not an error at all). `TestExporterDown_NeverFailsCommand` points a real exporter at `127.0.0.1:1` and asserts commands still reply `+OK`.

6. **Trace↔log correlation rides an slog fanout handler.** `telemetry.NewSlogHandler` tees the existing console handler and an `otelslog` OTLP handler; disabled, it returns the base handler *unchanged* (console byte-shape untouched — the M8 byte-compat value). A record logged via `…Context` inside a span carries the `trace_id`; converted the durability-breach + rewrite + auth logs to `…Context` so the high-value events correlate. `TestLogRecordCarriesTraceID` captures OTLP log records via a hand-rolled in-memory `sdklog.Exporter` and asserts a valid trace id.

## Why it mattered

- **"Observable" had to become a backed claim, not an adjective.** The release can't call the node observable while shipping zero signals. M16 makes it concrete: RED per command, a `connection → command → {store, aof}` trace tree, and trace-correlated logs, viewable from one `docker compose up`.
- **Additive means *provably* additive.** The whole point is that M16 does not touch the semver story. That's only true if disabled is a true no-op — hence the no-op-by-construction design and the parity benchmark, not just a claim in the roadmap.
- **Privacy is a design constraint, not a footnote.** No key names/values in metric labels (unbounded user data → Mimir cardinality blowup), opt-in salted-hash key capture on spans, passwords never in any signal. Written into SECURITY.md so the "safe-by-default" posture extends to telemetry.
