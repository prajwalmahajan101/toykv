## Decision / surprise

1. **The reader never needed touching — and that's the whole shape of M10.** The instinct with "add RESP3" is to reach for the codec on both sides. But clients send commands as RESP2 arrays of bulk strings *regardless of negotiated protocol*; RESP3 only changes replies (plus out-of-band push frames, which have no producer until v3). So `internal/resp/reader.go` is untouched. That single realization collapsed the blast radius from "rewrite the codec" to "add reply encoders + one command." Recorded as the load-bearing insight in ADR-0011.

2. **`WriteFrame(v)` → `WriteFrame(v, proto)` was the wrong first move; I reverted it mid-commit.** My first pass changed the signature to take `proto` everywhere. The compiler immediately showed why that's wrong: `WriteFrame` has ~8 callers that are *inherently RESP2* — AOF record encoding (`internal/aof/writer.go`, `rewriter.go`) and the outbound command path (`internal/client`). Those aren't talking to a negotiated client; forcing them to pass `resp.Proto2` is noise that misrepresents intent. Kept `WriteFrame(v)` as the RESP2 default and added `WriteFrameProto(v, p)` for the one caller that varies (the server reply path). Cleaner API, ~8 fewer churned call sites, and the method name now documents "this producer is RESP2 by nature."

3. **The protocol-aware writer is the single downgrade point.** Handlers return rich `resp.Value` kinds (`Map`, `Set`, `Double`, `Boolean`, `Null`, `Verbatim`, `Push`); `WriteFrameProto` emits native RESP3 at Proto3 and downgrades each to its RESP2 equivalent at Proto2 — map→flat array, null→`$-1`, bool→`:1/:0`, etc. This is Redis's own `addReply*` shape, and it's what makes M11 free: `HGETALL` will just return `resp.Map(...)` with zero writer changes.

4. **`connState` threading is churn I chose to pay now.** Every handler gained a `*connState` param most of them ignore (`_ *connState`). The alternative — special-casing `HELLO` outside the command table — dodges the churn but forfeits the seam M12 (auth gating in `dispatch`) and M13 (proto-aware `INFO`) both need. Paid once here; documented as the rejected alternative in ADR-0011.

5. **Migrated exactly two nulls, on purpose.** `GET` miss and `SET NX/XX` failure moved from `NullBulk()` to `Null()`. RESP3 clients now get `_`; RESP2 stays `$-1`, byte-identical to v1. This was the one scope decision that changed RESP3 wire bytes for a *common* command — asked before doing it. The payoff: the compat sweep tests a real RESP2-vs-RESP3 divergence, and go-redis `Protocol:3` decodes the miss to `redis.Nil` naturally.

## Why it mattered

- **The compat guarantee is mechanical, not aspirational.** Two layers of test pin it: writer goldens assert every RESP3 kind's Proto3 encoding *and* its Proto2 downgrade; the byte-level dual-protocol sweep (`resp3_compat_test.go`) replays every PRD §5.1 command over a live socket on both protocols and asserts exact wire bytes. RESP2 can't silently drift — that was the ADR-0001 golden contract's whole point.
- **Tests had to go byte-level because the reader is RESP2-only.** The existing `resp.Reader` can't parse `%`/`_`/etc., so RESP3 replies are asserted as raw bytes via `io.ReadFull(conn, len(want))`. This is actually *more* honest for a compat sweep than round-tripping through a parser — it tests the literal bytes on the wire.

## Blog-worthy?

Two quotable beats. First: *"Adding RESP3 didn't mean rewriting the codec — it meant realizing the reader never changes."* The reader-untouched insight is the kind of scope-collapse that reads well. Second: the `WriteFrame` signature revert — a small, honest "I made the API worse, then fixed it" that illustrates why *inherently-RESP2 producers* deserve a param-free default instead of a mandatory `Proto2` argument. Both are concrete, both are the sort of thing that goes bland if not captured now.
